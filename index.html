架构一览

一个入口，连接互联网和你的全部服务

左边是来自互联网的 HTTP、TCP、UDP 流量，右边是你的后端：通过标签自动发现的服务、站点文件里写明的服务器，以及通过 Connect 反向隧道接入的内网服务。中间的路由引擎负责转发，安全、流量治理、证书和观测在同一处完成。

服务发现 · Magic Ingress

后端注册即上线，网关零配置

做 API 网关时，网关上只为前端写一次站点；之后每个后端服务在注册时带上两个标签，就自动挂到同一个域名下。服务上线、扩容、下线都不用改网关配置，也不用重启。

  1. 服务注册后端在 Litemesh、Consul、Docker 或 Kubernetes 中注册，标签写在服务元数据或 Docker label 里。
  2. 网关实时感知LiteGate 订阅服务变化，在内存里生成路由，和站点文件里的前端合并到同一个域名，天然同源、没有跨域问题。
  3. 流量自动跟随实例新实例自动加入负载均衡，健康检查失败或下线自动摘除；用到新域名时证书照常自动申请。
服务标签使用指南
sites/app.yaml网关上只写这一次
site: app.example.com
spa: ./dist
docker-compose.yml后端自己声明
services:
  orders:
    image: acme/orders
    labels:
      litegate.http.host: app.example.com
      litegate.http.path_prefix: /api/orders
  users:
    image: acme/users
    labels:
      litegate.http.host: app.example.com
      litegate.http.path_prefix: /api/users
服务元数据注册时附带
# orders 服务注册时携带的标签
litegate.http.host=app.example.com
litegate.http.path_prefix=/api/orders
litegate.http.strip_path=true   # 可选：转发时去掉前缀
服务元数据命名资源写法
litegate.http.routers.orders.match.hosts=app.example.com
litegate.http.routers.orders.match.path_prefix=/api/orders
litegate.http.routers.orders.middlewares=orders-limit
litegate.http.middlewares.orders-limit.ratelimit.qps=100
litegate.http.services.orders.retry.attempts=2
litegate.http.services.orders.healthcheck.path=/healthz

https://app.example.com/ 是前端，/api/orders、/api/users 随服务注册自动出现。

Site YAML v2

一种配置语言，从三行到完整网关

路径就是键，动作就是值。简单站点几行写完；需要负载均衡、跨域、限流时，直接写在对应路由下面，不用换格式，也不需要额外插件。

前后端分流

/api 交给后端，其余交给单页应用，未知路由回退到 index.html。

site: app.example.com
/api: 127.0.0.1:8080
spa: ./dist

多个后端 + 去前缀

逗号分隔多个地址，默认轮询；strip_prefix 转发前去掉 /v1。

site: api.example.com
/v1:
  proxy: 10.0.0.5:8080, 10.0.0.6:8080
  strip_prefix: true

跨域 + 限流

治理规则和转发写在同一个路由下，预检请求由网关直接应答。

site: api.example.com
/api:
  proxy: localhost:8080
  cors:
    allowed_origins: [https://web.example.com]
  rate_limit: {rate: 10, key: ip}

顺序无关

路由按优先级和匹配精确度排序，写在文件里的先后不影响结果；匹配条件完全相同的两条路由直接报错，而不是静默覆盖。

从简写到完整，不换格式

需要精确路径、按方法或请求头匹配、命名服务复用时，在同一个文件里加 routes、services，简写和完整写法可以混用。

工具友好

就是 YAML：编辑器高亮、litegate -t 校验、Git 管理版本；AI 助手可以通过内置 MCP 直接创建和修改站点。

跨网络连接

内网发布、云上资产、统一出网

三种方向，三个能力，都跑在同一个 443 端口上，不需要再部署 frp、跳板机或单独的代理服务。

CONNECT

把内网服务发布到公网

内网节点主动拨向云端，家里和机房不用开放任何入站端口。一个 Cloud 可以接入多个 Home，每个 Home 只能发布被授权的域名。TLS 在内网终止，证书私钥不离开内网，云端看不到明文。

Connect 配置指南
Home · config.yaml
connect:
  client:
    enabled: true
    name: home
    remote: https://connect.example.com
    token_file: /etc/litegate/secrets/home.token
    publish_sites: true
FORWARD

在本机安全访问云上数据库

把 VPC 里的 MySQL、Redis、SSH 映射到开发者本机端口。服务端把域名锁定到一个 Stream，客户端无法改变目标；Stream 的 IP 限制、会话上限和超时照常生效。

数据库安全访问方案
开发机
$ litegate forward \
    --remote https://db-tunnel.example.com \
    --local 127.0.0.1:3306 \
    --token-file ./rds.token
FORWARD PROXY

无公网 IP 的机器统一出网

标准 HTTP CONNECT 正向代理，挂在 443 上按域名触发。支持账号认证和目标 ACL；开启防探测后，未认证的访问看起来就是一个普通网站。

Forward 与 Forward Proxy 对比
config.yaml
ingress_plugins:
  - name: egress
    type: forward_proxy
    entrypoints: [websecure]
    config:
      hosts: [proxy.example.com]
      username: ops
      password_env: LITEGATE_PROXY_PASSWORD
      probe_resistance: true

Notify Hub · 事件通知

HTTP 发一条消息，所有订阅方都收到

配置变更、任务完成、工单提醒，以前要部署 MQTT 服务，或者自己写 WebSocket 服务、维护连接表。现在网关就是通知中心：发布方只需一个 HTTP POST，浏览器、Go 服务和网关插件都能订阅；需要时还能离线续推。

以前
  • 部署并维护 MQTT 服务，或自建 WebSocket 服务
  • 每个客户端集成 MQTT / WebSocket SDK
  • 业务后端维护连接表、心跳、多实例广播
现在
  • 网关上多两条路由，不需要额外的服务
  • 发布方 HTTP POST，订阅方一个 HTTP 长连接
  • 鉴权、限额、监控直接复用网关已有的能力
  1. 发布任何能发 HTTP 的程序把消息 POST 到网关。不用 MQTT 客户端，也不用连接消息服务。
  2. 广播网关通过 NATS 把消息送到每个网关节点，多实例、多机房自动覆盖。
  3. 订阅浏览器和 Go 服务通过 SSE 订阅，网关插件声明主题直接接收。断线自动重连，连上先刷新一次状态，漏掉的消息由这次刷新补齐。
事件通知指南
sites/app.yaml
site: app.example.com
/notify/:                    # 发布：POST /notify/<主题>
  ip_restriction: { allow_ips: [10.0.0.0/8] }
  action:
    type: nats
    mode: publish
    subject_from: path.1       # /notify/config → notify.config
    subject_prefix: notify
    subject_allowlist: [config, order]
/events/config:              # 订阅
  use: login                  # 登录校验
  action:
    type: nats
    mode: subscribe
    subject: notify.config
    sse: { tenant: app }
任何语言状态变化后发一个信号
$ curl -X POST http://10.0.0.10/notify/config \
    -H "Content-Type: application/json" \
    -d '{"type":"config.changed","key":"store-001","version":42}'
app.js浏览器原生 API
const events = new EventSource('/events/config')
events.onopen = () => reloadAll()        // 连上先刷新
events.onmessage = e => reload(JSON.parse(e.data))
main.go只依赖标准库
sub := &notify.Subscriber{
    URL:     "https://app.example.com/events/config",
    OnOpen:  cache.ReloadAll,        // 连上先刷新
    OnEvent: cache.Apply,            // 按信号增量刷新
}
go sub.Run(ctx)                  // 自动重连、随机退避
provider.go插件自己定义主题
func (p *Provider) NotifySubjects() []string {
    return []string{"notify.tenant"}
}
func (p *Provider) HandleNotify(
    ctx context.Context, n plugin.Notification) error {
    if n.Resync { p.cache.InvalidateAll(); return nil }
    // 租户关闭：只删这个租户的缓存
    p.cache.Invalidate(tenantOf(n.Data))
    return nil
}

支持离线消息

需要逐条送达时启用 JetStream 持久化：离线的订阅方重连后从断点继续收，业务处理完再确认；一个订阅方确认，不影响其他订阅方。

可靠事件通知

后端不再持有长连接

推送、心跳、断线重连、慢客户端都在网关处理。业务后端还是普通的无状态 HTTP 服务，扩到多少个实例都不用考虑广播。

插件也是订阅方

IDS 插件可以放心缓存租户信息：只要声明 notify.tenant，租户在租户系统里一关闭，所有网关上的缓存秒级失效。

插件订阅通知

Encrypted ClientHello

连访问哪个网站都加密

普通 HTTPS 会在握手时明文暴露域名（SNI）。开启 ECH 后，网络上只能看到一个公共名称，真实域名被加密在 ClientHello 里，LiteGate 解密后照常按原域名选证书、走路由。

  • 自动生成 ECH 密钥，并通过 DNS Provider 发布 HTTPS（类型 65）记录
  • 网站继续使用普通 ACME 证书，不需要特殊证书
  • 支持多组公共名称，密钥可存放在文件或集群 KV 中
  • 没有启用 ECH 的客户端照常访问，不受影响
ECH 配置指南
config.yaml
ech:
  enabled: true
  public_name: ech.example.com   # 网络上唯一可见的名称
  dns_provider: cloudflare
  domains:                       # 需要隐藏的真实站点
    - app.example.com
    - admin.example.com

自动证书

家庭网络也能自动签证书

站点一配上域名就自动申请证书，到期前自动续期。80 端口连不进来的家庭网络，配好 DNS Provider 后整个区自动改走 DNS-01；失败会退避重试，不会把 CA 的限额打满。

  • HTTP-01、TLS-ALPN-01、DNS-01（泛域名）
  • 阿里云、Cloudflare、华为云、腾讯云内置，其他服务商可用插件扩展
  • On-Demand TLS：SaaS 客户自带域名，握手时按需签发
  • 本地 CA：*.localhost 开发环境也是受信任的 HTTPS
config.yaml · 家庭网络
auto_cert:
  dns_providers:
    - name: cloudflare
      type: cloudflare
      enabled: true
      domains: ["*.home.example.com"]
      config:
        api_token: env://CF_API_TOKEN
# 先签泛域名，之后新加的站点直接复用，
# 不在泛域名内的同区域名也会自动走 DNS-01

L4 + L7

网站和 TLS 服务共用 443

LiteGate 在 TLS 握手前读取 SNI，把匹配的连接整条转给 TCP 上游，其余照常进入 HTTPS。Redis TLS、gRPC 这类一开始就是 TLS 的协议可以直接共用 443；MySQL、PostgreSQL 这类先明文握手的协议，用上面的 Forward。

streams/redis.yaml
site: tcp://redis.example.com   # 按 SNI 匹配，自动挂到 443
proxy: 10.0.0.30:6380

平台能力

从一台 VPS 到多租户 SaaS

小项目只用前面那几行配置；业务长大以后，下面这些能力按需打开，不用换网关。

配置发布与回滚

开启 Release Control 后，修改先进草稿，校验并确认差异后再发布；每次发布都有历史，可以一键回滚。

多租户选路（IDS）

路由匹配后、转发前，由你的 Go 插件识别租户、决定放行或拒绝、选择租户专属实例并按租户限流。

集群配置与证书共享

站点、证书和 ECH 密钥可以统一放在 Litemesh / Consul KV，写一次全集群热加载，证书由一个节点签发、全员共享。

编译期插件

litegate build --with 把第三方插件编进二进制，覆盖 Stream、Action、中间件、负载均衡、DNS Provider 等扩展点。

内置 MCP

Claude Code、Cursor 等 AI 助手通过 MCP 查看站点、创建配置、热重载和排查错误。

安全与可观测

OIDC / JWT / API Key 鉴权、IP 限制、扫描防护，内置 Dashboard、访问日志、Prometheus 指标与链路追踪。

$ ./litegate
