Site YAML v2

比 Caddyfile 更好读的配置语言

路径就是键，动作就是值。简单站点和 Caddyfile 一样短；规则一多，差别就出来了：不用记指令执行顺序，跨域和限流直接写在路由下，不需要额外插件。

sites/app.yamlLiteGate
site: https://app.example.com
/api: 127.0.0.1:8080
spa: ./dist
CaddyfileCaddy
app.example.com {
  handle /api/* {
    reverse_proxy 127.0.0.1:8080
  }
  handle {
    root * ./dist
    try_files {path} /index.html
    file_server
  }
}

3 行对 10 行。SPA 回退是 spa: 一个键；/api 按路径段匹配，同时覆盖 /api 和 /api/...。

sites/api.yamlLiteGate
site: https://api.example.com
/v1:
  proxy: 10.0.0.5:8080, 10.0.0.6:8080
  strip_prefix: true
CaddyfileCaddy
api.example.com {
  handle_path /v1/* {
    reverse_proxy 10.0.0.5:8080 10.0.0.6:8080
  }
}

字段名就是含义。strip_prefix: true 不需要记住 handle 和 handle_path 的区别；多个后端默认轮询。

sites/api.yamlLiteGate
site: https://api.example.com
/api:
  proxy: localhost:8080
  cors:
    allowed_origins: [https://web.example.com]
  rate_limit: {rate: 10, key: ip}
CaddyfileCaddy + caddy-ratelimit
{
  order rate_limit before reverse_proxy
}
api.example.com {
  @preflight method OPTIONS
  handle /api/* {
    header Access-Control-Allow-Origin https://web.example.com
    header Access-Control-Allow-Methods "GET, POST, OPTIONS"
    respond @preflight 204
    rate_limit {
      zone api {
        key    {remote_host}
        events 10
        window 1s
      }
    }
    reverse_proxy localhost:8080
  }
}

治理就地声明。Caddy 没有内置 CORS 和限流：跨域要手写响应头和预检，限流需要另外编译第三方插件，并在全局声明指令顺序。

顺序无关

路由按优先级和匹配精确度排序，写在文件里的先后不影响结果；匹配条件完全相同的两条路由直接报错，而不是静默覆盖。

从简写到完整，不换格式

需要精确路径、按方法或请求头匹配、命名服务复用时，在同一个文件里加 routes、services，简写和完整写法可以混用。

工具友好

就是 YAML：编辑器高亮、litegate -t 校验、Git 管理版本；AI 助手可以通过内置 MCP 直接创建和修改站点。

跨网络连接

内网发布、云上资产、统一出网

三种方向，三个能力，都跑在同一个 443 端口上，不需要再部署 frp、跳板机或单独的代理服务。

CONNECT

把内网服务发布到公网

内网节点主动拨向云端，家里和机房不用开放任何入站端口。一个 Cloud 可以接入多个 Home，每个 Home 只能发布被授权的域名。TLS 在内网终止，证书私钥不离开内网，云端看不到明文。

Connect 配置指南
Home · config.yaml
connect:
  client:
    enabled: true
    name: home
    remote: https://connect.example.com
    token_file: /etc/litegate/secrets/home.token
    publish_sites: true
FORWARD

在本机安全访问云上数据库

把 VPC 里的 MySQL、Redis、SSH 映射到开发者本机端口。服务端把域名锁定到一个 Stream，客户端无法改变目标；Stream 的 IP 限制、会话上限和超时照常生效。

数据库安全访问方案
开发机
$ litegate forward \
    --remote https://db-tunnel.example.com \
    --local 127.0.0.1:3306 \
    --token-file ./rds.token
FORWARD PROXY

无公网 IP 的机器统一出网

标准 HTTP CONNECT 正向代理，挂在 443 上按域名触发。支持账号认证和目标 ACL；开启防探测后，未认证的访问看起来就是一个普通网站。

Forward 与 Forward Proxy 对比
config.yaml
ingress_plugins:
  - name: egress
    type: forward_proxy
    entrypoints: [websecure]
    config:
      hosts: [proxy.example.com]
      username: ops
      password_env: LITEGATE_PROXY_PASSWORD
      probe_resistance: true

Encrypted ClientHello

连访问哪个网站都加密

普通 HTTPS 会在握手时明文暴露域名（SNI）。开启 ECH 后，网络上只能看到一个公共名称，真实域名被加密在 ClientHello 里，LiteGate 解密后照常按原域名选证书、走路由。

  • 自动生成 ECH 密钥，并通过 DNS Provider 发布 HTTPS（类型 65）记录
  • 网站继续使用普通 ACME 证书，不需要特殊证书
  • 支持多组公共名称，密钥可存放在文件或集群 KV 中
  • 没有启用 ECH 的客户端照常访问，不受影响
ECH 配置指南
config.yaml
ech:
  enabled: true
  public_name: ech.example.com   # 网络上唯一可见的名称
  dns_provider: cloudflare
  domains:                       # 需要隐藏的真实站点
    - app.example.com
    - admin.example.com

自动证书

家庭网络也能自动签证书

站点一配上域名就自动申请证书，到期前自动续期。80 端口连不进来的家庭网络，配好 DNS Provider 后整个区自动改走 DNS-01；失败会退避重试，不会把 CA 的限额打满。

  • HTTP-01、TLS-ALPN-01、DNS-01（泛域名）
  • 阿里云、Cloudflare、华为云、腾讯云内置，其他服务商可用插件扩展
  • On-Demand TLS：SaaS 客户自带域名，握手时按需签发
  • 本地 CA：*.localhost 开发环境也是受信任的 HTTPS
config.yaml · 家庭网络
auto_cert:
  dns_providers:
    - name: cloudflare
      type: cloudflare
      enabled: true
      domains: ["*.home.example.com"]
      config:
        api_token: env://CF_API_TOKEN
# 先签泛域名，之后新加的站点直接复用，
# 不在泛域名内的同区域名也会自动走 DNS-01

L4 + L7

网站和 TLS 服务共用 443

LiteGate 在 TLS 握手前读取 SNI，把匹配的连接整条转给 TCP 上游，其余照常进入 HTTPS。Redis TLS、gRPC 这类一开始就是 TLS 的协议可以直接共用 443；MySQL、PostgreSQL 这类先明文握手的协议，用上面的 Forward。

streams/redis.yaml
site: tcp://redis.example.com   # 按 SNI 匹配，自动挂到 443
proxy: 10.0.0.30:6380

平台能力

从一台 VPS 到多租户 SaaS

小项目只用前面那几行配置；业务长大以后，下面这些能力按需打开，不用换网关。

服务发现与打标上线

对接 Consul、Litemesh、Docker、Kubernetes。后端注册时带上标签，就自动挂到对应站点的路由下，前后端各自发布。

多租户选路（IDS）

路由匹配后、转发前，由你的 Go 插件识别租户、决定放行或拒绝、选择租户专属实例并按租户限流。

集群配置与证书共享

站点、证书和 ECH 密钥可以统一放在 Litemesh / Consul KV，写一次全集群热加载，证书由一个节点签发、全员共享。

编译期插件

litegate build --with 把第三方插件编进二进制，覆盖 Stream、Action、中间件、负载均衡、DNS Provider 等扩展点。

内置 MCP

Claude Code、Cursor 等 AI 助手通过 MCP 查看站点、创建配置、热重载和排查错误。

安全与可观测

OIDC / JWT / API Key 鉴权、IP 限制、扫描防护，内置 Dashboard、访问日志、Prometheus 指标与链路追踪。

快速开始

一分钟拿到第一个响应

安装

从 Releases 下载对应平台的二进制，或用 Go 安装：

$ go install \
  github.com/jamesleeon/LiteGate/cmd/litegate@latest

写一个站点

在工作目录创建 sites/hello.yaml：

site: localhost
respond: "Hello, LiteGate!"

启动

没有 config.yaml 也能直接跑：

$ ./litegate
$ curl http://localhost/
Hello, LiteGate!
