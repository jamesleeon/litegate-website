# 多副本状态与故障隔离

多副本不会自动把网关内存态变成共享状态。按实际启用的存储和插件规划一致性，不能假设配置了 Redis 就共享全部状态。

| 状态 | 副本间行为 |
|---|---|
| scan_protection 风险与封禁 | 每进程独立，没有共享封禁 |
| proxy_cache | 本地内存，命中率按副本分散 |
| 熔断与被动健康 | 每进程独立，反映各自访问结果 |
| 限流 | 按选用的机制判断；本地桶不共享，Redis 机制需单独配置 |
| IDS 会话与缓存 | 由 Provider 自行管理，内核不保证 Redis 会话 |
| Sticky 会话 | 按 Cookie 与相关密钥配置检查，不能默认假设跨副本可解 |
| NATS 离线订阅 | 依赖 JetStream；所有网关共享 ACK 密钥及相同业务身份 |
| 配置与证书 | 显式配置共享后端或同步方式，检查权限与故障恢复 |

本地熔断快速拒绝不算被动健康失败；在请求可重放时，可安全改选实例，无退避且不消耗普通错误重试预算。LB 仍可能选到熔断节点，因此不要把本地快速拒绝描述为提前从发现池删除。

扫描防护多副本时，轮询到另一个副本可能尚未封禁。需要统一阻断时，在前置入口统一实施 IP 策略。上线验证应包含节点切换、配置更新、缓存失效与凭据轮换。
