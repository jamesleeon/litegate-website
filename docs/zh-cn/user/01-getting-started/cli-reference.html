CLI 命令行参考

LiteGate 通过命令行参数控制启动行为和工具功能。

基础用法

litegate [options]

参数列表

运行模式

参数 默认值 说明
-config <path> config.yaml 指定配置文件路径。也可通过 LITEGATE_CONFIG 环境变量设置。
-log-level <level> 配置文件中的值 覆盖日志等级：debug, info, warn, error。
-enable-metrics false 启用 Prometheus 指标导出。

工具模式

参数 说明
-init 生成 config.example.yaml 并创建 sites/, streams/, certs/ 默认目录。
-example 在 ./sites 目录下生成各类示例站点配置文件。
-hash <password> 为 Dashboard、Basic Auth 或内置 SSO 用户密码生成 bcrypt 哈希值。
-hashfile <path> 计算文件 SHA256，输出一行 64 字符的小写十六进制校验和后退出，可直接用于 SPA/serve KV 的 sha256 字段。
-secret 输出一行 64 字符的十六进制随机密钥（32 个随机字节），可用于 SSO 的 auth.secret。
-gen-secret 输出随机密钥的 Hex、Base64 和 Base64URL 三种带标签格式。
-t 测试配置文件语法并退出（不启动服务）。类似 nginx -t。

插件与定制构建子命令

命令 说明 详见
litegate build [flags] 动态编译带自定义插件的 LiteGate 二进制（类似 xcaddy）。支持 --with、--replace、-o。 插件构建指南
litegate plugins list 列出当前二进制中编入的所有公共插件列表（类型、名称、版本、契约版本）。 插件 CLI 参考
litegate plugins inspect <kind>/<name> 查看指定已编入插件的详细元数据与官方 YAML 配置示例模板。 插件 CLI 参考
litegate plugins doctor 对当前已编入插件执行健康检查，诊断 Manifest 完整性与 APIVersion 兼容性。 插件 CLI 参考

运维与连接子命令

命令 说明 详见
litegate mcp [-config <path>] [-log-level <level>] 以 stdio 方式运行 MCP 服务，供 Claude Code、Cursor 等 AI 客户端拉起。日志写到 stderr。 MCP 能力表
litegate forward --remote <url> --local <addr> --token-file <file> Forward 客户端：把远端 Stream 映射到本机端口；也可用 --config 读取 YAML。litegate forward token --output <file> 生成令牌。 Forward 与 Connect
litegate connect [http] --remote <url> --name <name> --domain <host> --upstream <url> 用命令行把本机 HTTP 服务通过 Connect 发布出去；litegate connect token --output <file> 生成令牌。 Connect 命令行
litegate systemd [options] 输出 systemd 单元文件（-user、-workdir、-config、-name 等）。 systemd 部署
litegate secret keygen|pubkey|encrypt 生成本机密钥对，把凭据加密为 enc:// 引用，配置文件中不出现明文。 Sealed Secrets
litegate ech withdraw -config <path> 撤回已发布的 ECH DNS 记录（先停止 ECH 实例）。 ECH
litegate healthcheck [-config <path>] [-addr <addr>] 探测本机网关健康端点，适合容器 HEALTHCHECK。 生产部署

Consul 引导参数

参数 环境变量 说明
-consul-addr LITEGATE_CONSUL_ADDR Consul 地址。指定后将从 Consul KV 远程加载配置。
-consul-token LITEGATE_CONSUL_TOKEN Consul ACL Token。
-consul-config-key LITEGATE_CONSUL_KEY Consul 中存储主配置的 KV 路径。默认 litegate/config/main。

Litemesh 引导参数

参数 环境变量 说明
-litemesh-addr LITEGATE_LITEMESH_ADDR Litemesh 地址。指定后将从 Litemesh KV 远程加载配置。
-litemesh-token LITEGATE_LITEMESH_TOKEN Litemesh Auth Token。
-litemesh-config-key LITEGATE_LITEMESH_KEY Litemesh 中存储主配置的 KV 路径。默认 litegate/config/main。
-sync-litemesh — 将本地配置文件同步推送到 Litemesh KV，然后退出。

使用示例

零配置启动

litegate

默认监听 :80 (HTTP) 和 :443 (HTTPS)，自动扫描 ./sites 目录。

指定配置文件

litegate -config /etc/litegate/config.yaml

初始化项目结构

litegate -init

生成 config.example.yaml 和 sites/, streams/, certs/ 目录。

生成 Dashboard 密码

litegate -hash "your-password"
# 输出 Bcrypt 哈希值，复制到 config.yaml 的 dashboard.password 字段

生成 SSO 会话密钥

litegate -secret
# 将整行输出填入站点配置的 auth.secret

每次运行都生成新的随机密钥，不读取站点配置，也不启动服务。配置后保持密钥稳定；更换密钥会使原有登录 Cookie 失效。用户密码哈希使用 litegate -hash 'your-password' 单独生成。

测试配置语法

litegate -t
# litegate: the configuration file config.yaml syntax is ok
# litegate: sites configuration in ./sites syntax is ok

从 Litemesh 远程引导启动

litegate -litemesh-addr 127.0.0.1:8787 -litemesh-token mytoken

将本地配置同步到 Litemesh

litegate -config config.yaml -sync-litemesh -litemesh-addr 127.0.0.1:8787

环境变量

以下环境变量在命令行参数未指定时生效：

环境变量 说明
LITEGATE_CONFIG 配置文件路径
LITEGATE_CONSUL_ADDR Consul 地址
LITEGATE_CONSUL_TOKEN Consul ACL Token
LITEGATE_CONSUL_KEY Consul KV 配置路径
LITEGATE_LITEMESH_ADDR Litemesh 地址
LITEGATE_LITEMESH_TOKEN Litemesh Auth Token
LITEGATE_LITEMESH_KEY Litemesh KV 配置路径

配置文件中的字段也支持 ${VAR_NAME} 环境变量语法。

计算 SPA/serve KV 发布包校验和

litegate -hashfile main-12.zip

将输出整行填入 KV JSON 的 sha256 字段。计算的是上传的 ZIP 文件本身的原始字节，不是解压后的目录；无需配置文件，也不启动服务。
