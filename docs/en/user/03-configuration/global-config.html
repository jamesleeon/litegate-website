Gateway configuration reference (config.yaml)

config.yaml defines LiteGate's listeners, certificates, service discovery, observability, caching, authentication and MCP exposure.

MCP's get_gateway_config_schema returns this file verbatim. The fields here must stay in step with internal/config/types.go.

0. Mode

# performance: high-throughput mode (default). Metrics, access logs, tracing and the dashboard still work when enabled
# observability: records routing details for every request and always feeds the dashboard live stream
mode: "performance"

performance (the default) only skips per-request accounting that nothing consumes: enabling metrics, dashboard, log.access_log or tracing keeps that feature fully working, and the live request stream (read by the dashboard and the MCP get_recent_requests tool) keeps flowing while the dashboard or MCP SSE is on. Use mode: observability to always record routing details.

1. Listeners and entrypoints (multiple ports / network interfaces)

LiteGate supports Traefik-style multiple ingress listeners, so different sites or an internal management interface can bind to different ports or to a specific physical interface (SO_BINDTODEVICE).

entrypoints:
  web:
    address: ":80"
  websecure:
    address: ":443"
    tls: true
  # internal:
  #   address: ":8080"
  #   interface_name: "eth0"         # Optional. Bind a Linux network device, following its DHCP address

# Legacy port configuration; when entrypoints is present, entrypoints wins
http:
  port: 80
  https_port: 443
  response_header_timeout: 60    # Optional. Default response-header timeout, in seconds
  # upstream_transport_shards: 1  # Optional. Connection pools per upstream endpoint, to cut pool-lock contention under high concurrency; default 1 = off
  # upstream_buffer_size: 32768   # Optional. Upstream HTTP/1 connection read/write buffer in bytes (4096..65536, default 32768); large bodies bypass it
  # upstream_client: fast         # Optional. Default fast: plaintext HTTP/1.1 upstreams use a synchronous pool (lower overhead) and TLS/mTLS/HTTP2/gRPC/WebSocket automatically use the standard client; standard uses Go's net/http Transport everywhere
  # listen_backlog: 65535        # Optional. Windows only: TCP accept queue length (1..65535, default 65535). Needs a `make windows` build; Go's default is about 200, so connection bursts get refused
  # drain_delay: 5               # drain wait in seconds; omitted = auto, 0 = off, N = fixed N seconds
  # drain_delay_ms: 250          # optional millisecond override, taking precedence over drain_delay

Shutdown drain (drain_delay): on a stop signal, /readyz starts returning 503 and LiteGate actively deregisters from Consul / litemesh, then waits before closing its listeners so load balancers in front stop sending new requests.

  • Omitted (default, auto): waits only when something is actually watching — when registered with Consul / litemesh it deregisters first and waits 1 second; when /readyz was probed within the last 2 minutes (K8s readinessProbe, a cloud load balancer) it waits 5 seconds; a standalone instance nobody probes stops immediately.
  • drain_delay: 0 disables the wait; drain_delay: N always waits N seconds (e.g. when the load balancer only does TCP checks, which auto-detection cannot see).
  • Press Ctrl-C again (or send a second SIGTERM) during the wait to skip it.
  • Upgrading: configs generated by older versions contain drain_delay: 5, which counts as an explicit setting and keeps the 5-second wait; delete that line to use auto mode.

interface_name binds a specific Linux network device and follows its DHCP address. The legacy http block still works; when entrypoints is present, entrypoints wins.

1.1 Ingress plugins

Compiled ingress plugins handle HTTP requests on explicitly selected entrypoints before site matching and path normalization. Bindings execute in array order; unhandled requests continue to the next plugin and then the site router. No plugins are enabled by default. Names must be unique and entrypoints explicit. Missing plugins, unknown entrypoints and invalid plugin options reject configuration.

# The standard binary includes forward_proxy; declare a websecure TLS entrypoint first.
ingress_plugins:
  - name: developer-egress
    type: forward_proxy
    entrypoints: [websecure]
    config:
      username: developer
      hosts: [proxy.example.com]
      password: '$2a$10$REPLACE_WITH_COMPLETE_BCRYPT_HASH'
      probe_resistance: true
      hide_ip: true
      hide_via: true
      allowed_destinations: [example.org, "*.example.org"]
      allowed_ports: [80, 443]

Global ingress security runs first. Handled requests do not enter site middleware ; the host records access logs, metrics and dashboard traffic under ingress:<binding name>. The plugin owns authentication and destination policies. Internally injected Forward/Connect traffic skips this chain. Failed candidate initialization keeps the active instances; successful reloads drain old instances for http.shutdown_grace (30 seconds when unset), then cancel their host context and close them with a deadline. Shutdown closes their owned connections immediately. Generate the full bcrypt hash with litegate -hash 'your-password' and place it in password; clients use the original password. Alternatively set password_env to read the original password from an environment variable. Configure exactly one; plaintext password is rejected. Optional hosts matches TLS SNI, not CONNECT's destination Host; unmatched, non-TLS or missing-SNI requests fall through. Configure a normal or catch-all Site for unauthenticated requests when probe resistance is enabled. A shared website listener must configure hosts or enable probe_resistance, otherwise legitimate absolute-form requests may receive 407. Changing only the value of the environment variable named by password_env does not rebuild an unchanged binding; change binding configuration or restart to load it. Successful bcrypt authentication caches the header SHA-256 digest for 5 minutes, renewing the TTL on cache hits with constant-time comparison; each instance admits at most two concurrent bcrypt checks, waiting for admission for at most 100ms subject to the request context. Wildcards do not grant access to local interface addresses, 64:ff9b::/96, 240.0.0.0/4 or 198.18.0.0/15; intentional access requires explicit IP/CIDR rules. Each resolved address has its own dial timeout. Interface addresses are cached for 30 seconds and refreshed on demand. A cloud public IP behind 1:1 NAT may not appear on the interfaces; add it to denied_destinations to block connections back to the gateway. Changing only shutdown_grace keeps the reused instance’s original grace period; change the binding or restart to adopt the new value. HTTP/2/3 end both directions when download ends; half-close is retained only for hijacked HTTP/1 connections. hide_ip and hide_via default to true, removing existing client-IP and Via headers from forwarded HTTP requests. Setting them to false appends the client IP to Forwarded and LiteGate to Via respectively. CONNECT payloads are never rewritten. The plugin supports HTTP/1.1 forwarding and HTTP/1.1, HTTP/2 and HTTP/3 CONNECT through the public RegisterIngress API; see examples/plugins/ingress/forwardproxy/README.md.

1.2 SNI / L4 routing on shared 443

entrypoints.websecure.routes inspects the TLS ClientHello before HTTPS termination and dispatches connections to an L4 backend or a named Stream. Unmatched hostnames continue to normal HTTPS sites. Explicit transport routes currently require websecure with tls: true.

Direct passthrough to a TLS backend

Place this configuration in config.yaml. Connections for tcp.example.com pass through to the TLS backend; LiteGate handles HTTPS for other hostnames:

entrypoints:
  web:
    address: ":80"
  websecure:
    address: ":443"
    tls: true
    default: http
    on_non_tls: reject
    on_no_sni: reject
    inspect:
      timeout: 5s
      max_pending: 2048
      per_ip_pending: 16
    routes:
      - name: private-tls
        match:
          sni: tcp.example.com
        handle:
          proxy: tcp://127.0.0.1:444

handle.proxy does not terminate TLS. The backend must start a TLS handshake from the first byte and hold the appropriate certificate. TCP Unix sockets such as unix:///run/service/tls.sock are also supported.

Recommended: generate routes from Stream site shorthand

Simple configurations do not need explicit routes. Keep the global websecure listener and define streams/database.yaml:

site: tcp://db.example.com
name: database
proxy: 127.0.0.1:3306

This attaches to websecure and generates the SNI route automatically. Do not repeat the hostname in config.yaml. TLS passes through by default. To terminate TLS in LiteGate, configure Stream tls.enabled: true and a certificate source; the backend specified by proxy then receives plain TCP.

For explicit routing to an existing Stream, merge the following route into entrypoints.websecure.routes. The Stream named database must exist and use listen: false. Choose exactly one of handle.proxy and handle.stream per route:

entrypoints:
  websecure:
    address: ":443"
    tls: true
    routes:
      - name: database
        match:
          sni: db.example.com
        handle:
          stream: database
Field Meaning
match.sni One hostname or a list; supports *.example.com.
match.sni_regex SNI regular expressions; prefer sni for simple names.
match.alpn Optional restriction to protocols offered in ClientHello, such as [h2]; case-sensitive.
handle.proxy TCP / Unix socket backend receiving the original TLS bytes.
handle.stream Existing named Stream applying its TLS, ACL and L4 proxy policies.
default Unmatched routes fall back to HTTP/HTTPS processing; only http is supported.
on_non_tls, on_no_sni Configure http or reject for non-TLS / missing SNI.
inspect ClientHello inspection timeout and concurrency limits.

Explicit routes for the same SNI without an ALPN restriction take precedence over generated Stream routes. ALPN-scoped explicit routes claim only those protocols; the generated route can still handle the rest. Plain TCP and UDP have no TLS SNI and cannot use this mechanism for hostname routing. UDP/QUIC does not use these TCP 443 routes. Avoid unintentionally assigning the same hostname to an L4 Stream and an HTTP site: SNI dispatch happens before HTTP routing. See the L4 guide for complete Stream scenarios.

2. Static TLS

tls:
  enabled: false
  certs_dir: "./certs"

  # Local CA (self-signed and self-trusted, the equivalent of Caddy's tls internal)
  local_ca: false                       # issue leaf certificates for local domains on demand
  local_ca_domains: [".localhost", ".test"]   # allow-list of issuable domains (a leading dot means suffix match)
  local_ca_trust: false                 # install into the system trust store on first generation (local development only)

The local CA is the equivalent of Caddy's tls internal: it self-signs leaf certificates on demand for local domains. In local_ca_domains, a leading dot means suffix match. local_ca_trust installs the CA into the system trust store on first generation — enable it for local development only.

3. Auto-Cert

Setting auto_cert.enabled: false disables automatic issuance and renewal, including TLS handshakes and hot reloads. Enabled dns_providers groups are prepared before site certificates. Sites covered by a configured wildcard wait for that group; a failed group does not trigger a separate HTTP-01 order. Wildcards use DNS-01.

Auto-Cert is enabled by default; set enabled: false to disable issuance. Concrete domain sites using the standard HTTPS listener automatically prepare certificates after TCP 443 binds successfully. Existing valid exact, SAN, or wildcard certificates are reused first; missing certificates default to HTTP-01. HTTP-only web bindings, IP addresses, and wildcard routing patterns are excluded.

Site https: true controls HTTP-to-HTTPS redirects independently of issuance. HTTP-01 requires DNS pointing to this gateway and publicly reachable TCP 80. on_demand.enabled enables the additional SaaS authorization flow for domains not configured in advance; ordinary configured sites do not need it.

auto_cert:
  enabled: true
  email: "litegate@example.com" # Default placeholder; replace if your CA requires a real address
  domains: []                    # legacy field, kept for compatibility
  certs_dir: "./certs"
  default_challenge: "http"      # default challenge type: "http" (port 80) or "tls-alpn" (port 443)
  storage_secret: ""             # Optional: symmetric key encrypting the ACME account private key (>= 32 bytes)

  # Multiple CA configuration
  ca_provider: "letsencrypt"     # letsencrypt, zerossl, google, custom
  acme_url: ""                   # custom ACME directory URL (required when ca_provider is custom)
  acme_ca_cert: ""               # private ACME root certificate path, or inline PEM
  acme_headers: {}                # extra headers for private ACME requests
  eab_kid: ""                    # External Account Binding key ID (ZeroSSL / GTS)
  eab_hmac: ""                   # External Account Binding HMAC key (ZeroSSL / GTS)

  provider: ""                   # legacy single-provider mode
  provider_config: {}

  dns_providers:
    - name: "aliyun-main"
      type: "aliyun"
      enabled: true
      domains: ["*.example.com", "example.com"]
      ddns:
        enabled: true
        ipv4: ""
        ipv6: ""
        sync_a: true
        sync_aaaa: true
        domains: ["*.example.com"]
      config:
        access_key_id: "..."
        access_key_secret: "..."

  renew_days: 10
  check_interval: 24
  use_staging: false
  propagation_dns: ["223.5.5.5", "114.114.114.114"]
  bootstrap_dns: ""

  dns_update:
    enabled: false
    auto_service_host_sync: false
    ip: ""
    key_prefix: "litedns/v1/records/"
    node_id: ""
    record_ttl: 30
    heartbeat_interval: 30s

  on_demand:
    enabled: false
    ask: "http://your-api/check-domain"
    kv_prefix: ""
    saas_template_site: ""

  webhook_url: ""
  webhook_token: ""

Field reference:

Field Type Description

acme_url string Custom ACME directory URL. Required when ca_provider=custom

3.1 Encrypted ClientHello (ECH)

Enable browser-to-gateway ECH in the main configuration using an existing enabled DNS provider:

ech:
  enabled: true
  groups:
    - public_name: ech.example.com
      dns_provider: aliyun-main
    - public_name: ech.example.net
      dns_provider: cloudflare-main
  storage: file
  # For shared storage:
  # storage: kv
  # kv:
  #   provider: litemesh  # or consul, reuse the existing connection
  #   key_prefix: litegate/ech/mycluster/
  # key_prefix: litegate/ech/mycluster/

Disabled by default. Requires auto_cert.enabled: true, the websecure TCP listener on port 443, site TLS policies permitting TLS 1.3, and a built-in Aliyun or Cloudflare provider. Names must be concrete ASCII hostnames. Sites need direct A/AAAA records, without CNAME; Cloudflare records must be DNS only.

LiteGate arranges the public-name certificate, persists ECH keys, and publishes HTTPS DNS records with TTL 600. Keys rotate every 7 days; old keys stay accepted for 14 days after no potentially published records reference them. Failed writes retry every minute, and unmanaged HTTPS records are never overwritten. Configuration changes require a restart. Persist and back up auto_cert.certs_dir/ech/<public_name>/state.json (falling back to tls.certs_dir; matching legacy single-group state directories remain in use). Auto storage encrypts and shares state through Consul/LiteMesh only when config_watch is enabled; a publisher lease selects one DNS writer. Explicit storage: file supports one instance; storage: kv requires kv.provider (litemesh or consul) and kv.key_prefix. Root KV prefixes are parent directories; group prefixes are exact, and the state/publisher keys are appended. Explicit KV with local site files warns that every node must have identical sites. Withdraw HTTPS records and wait for DNS caches before disabling ECH. See ECH for deployment details.

6. Service discovery

service_discovery:
  catalogs:
    - enabled: false
      provider: "consul"          # consul / discovery
      name: ""                    # plugin discovery instance name, unique within a type
      config: {}                  # plugin-specific key/value configuration
      url: "127.0.0.1:8500"
      service_name: ""
      resolve_via: ""             # consul / litemesh
      default_domain: ""
      auth_mode: "disabled"       # disabled / auto
      token: ""
      namespace: ""
      jwt_auth_url: ""
      md5_auth_url: ""

    - enabled: false
      provider: "docker"
      socket_path: "/var/run/docker.sock"
      network_mode: "internal"     # internal (container network IP) or external (host port-mapped IP)
      swarm_mode: false            # explicit Swarm mode
      swarm_auto_detect: false     # opt in to manager-only detection

  tag_entrypoints:
    allowed_ports: []              # ports service tags may open (HTTP entrypoints and TCP/UDP streams), e.g. [8080, 15432]
  path_ingress: true             # Magic Ingress path routing (http://gateway/<service>/...): only for services without their own Router, and only on unmatched or catch-all hosts

Service tags (litegate.entrypoints.<name>.address, litegate.tcp.port, litegate.udp.port) may open a listener only on a port listed in tag_entrypoints.allowed_ports, and never with the name or port of an entrypoint in this file. When the list is empty, tags cannot open ports and may only reference existing entrypoints (web and websecure by default). See the Service Tags Guide.

network_mode selects between the container network IP (internal) and the host port-mapped IP (external). Swarm detection is opt-in through swarm_auto_detect: true or LITEGATE_SWARM_AUTO_DETECT=true; swarm_mode: true explicitly enables Swarm without detection. Detection failures reject startup rather than silently selecting standalone mode.

Docker catalogs also accept constraints, a strict expression composed of Label("key", "value"), LabelRegex("key", "regex"), !, &&, ||, and parentheses. It filters original container/Service labels on complete snapshots and event refreshes, including declarations with zero Tasks. Invalid expressions reject startup. For example: constraints: 'Label("team", "payments") && !LabelRegex("environment", "^test$")'.

An SSH endpoint uses pure Go SSH and executes the fixed command docker system dial-stdio; the remote host must provide Docker CLI access for that user. The same client performs Swarm detection and later discovery calls. Operator authentication and host trust are configured on the catalog:

socket_path: "ssh://root@192.168.50.44:22"
ssh:
  password_env: "LITEGATE_DOCKER_SSH_PASSWORD"
  known_hosts_file: "/etc/litegate/known_hosts"
  connect_timeout: "10s"
  # private_key_file: "/etc/litegate/docker_ed25519"
  # agent_socket: "/run/ssh-agent.sock"

The password comes only from the named environment variable; URL passwords are rejected. Private keys and an SSH agent are optional operator alternatives. With no explicit authentication, SSH_AUTH_SOCK is used. Host verification uses the configured known_hosts file (default ~/.ssh/known_hosts) and negotiates algorithms matching pinned keys; unknown or changed keys fail. Connection setup, authentication and remote execution share the bounded connect_timeout. Established HTTP streams outlive their initial dial context and close when the client stops or a stream deadline expires.

catalogs is an array. The old single-object catalog form is gone from the current code. An external discovery provider uses its registered name as provider, keeps its own settings under config, and can use name to distinguish several instances of the same type.

cache:

    enabled: false

    username: ""

proxy_cache_max_entries bounds local response-cache entries. Select cache.proxy_cache.backend: redis explicitly for shared multi-node responses; enabling Redis alone does not switch this backend. Connections prefer enabled cache.redis, then global redis. Configure Redis capacity independently. Redis failures bypass caching; stale responses are disabled by default. Successful proxy writes can invalidate named read routes with on_success.invalidate_proxy_cache. Dashboard POST /api/proxy-cache/purge supports all/site/route/key scopes with existing authentication. addr is an alias for address; addrs lists Redis Cluster nodes.

Go runtime (runtime)

Tunes the Go garbage collector (GC). When omitted, Go's defaults apply and behavior is unchanged.

runtime:
  gc_percent: 200        # same as GOGC, 25-1000; omit for Go's default of 100
  memory_limit: 1GiB     # same as GOMEMLIMIT, units B/KiB/MiB/GiB/TiB, at least 64MiB
  • gc_percent: how far, as a percentage of the live heap, the heap may grow before the next collection. LiteGate keeps little resident memory, so under the default it can collect dozens of times per second at high load; 200 noticeably reduces collections (about +13% throughput for a respond site on 16 vCPUs) at the cost of more memory.
  • memory_limit: a soft memory cap; near it the collector runs earlier and more often. Set it whenever you raise gc_percent so memory cannot grow unbounded; keep it below the machine or container memory with headroom for other processes. Raising gc_percent without a limit logs a startup warning.
  • An explicitly set GOGC / GOMEMLIMIT environment variable takes precedence; the matching field is ignored with a warning.
  • Changing runtime requires a process restart; hot reload rejects the change.

15. Real IP

real_ip:
  # Trusted reverse proxy / load balancer IPs, whose X-Forwarded-For the gateway resolves the real client IP from
  trusted_proxies:
    - "127.0.0.1/32"
    - "10.0.0.5/32"
  # Internal client IPs/ranges allowed to perform east-west instance routing via X-Selector-Sid
  selector_trusted_clients:
    - "127.0.0.1/32"
    - "10.0.0.0/8"

  • trusted_proxies: which upstream proxies the gateway trusts when resolving the real client IP from X-Forwarded-For. Normally just the specific IPs of your front-facing load balancers. Empty by default: no peer is trusted, X-Forwarded-For is ignored and the client IP is the direct connection address. When nginx or another proxy runs on the same host in front of LiteGate, add 127.0.0.1 explicitly. Per-IP limits use the client address resolved at ingress, never the raw request header. XFF is honored only when the direct peer belongs to real_ip.trusted_proxies (or a Unix ingress protected by filesystem permissions). All same-name fields form one chain, scanned right to left for the first untrusted IP; IPv4/IPv6 representations are canonicalized. Invalid or empty boundary hops fall back to the direct peer. The front proxy must overwrite incoming XFF or append the client IP it actually observes on the right of the complete chain. A gateway cannot authenticate client-supplied addresses blindly passed through by its trusted proxy. Do not trust public client networks, 0.0.0.0/0 or ::/0.

  • selector_trusted_clients: the networks allowed to perform east-west instance routing via X-Selector-Sid. Only requests originating inside these ranges may have that header honoured for physical instance isolation; a X-Selector-Sid arriving from anywhere else is stripped at ingress, so it cannot be forged externally. If unset, this falls back to trusted_proxies.

18. Scan protection

scan_protection blocks scanners dynamically using a threat score, banning the source IP when it probes sensitive paths (.git, .env) or non-existent APIs.

scan_protection:
  enabled: false                      # master switch, off by default. Can be toggled at runtime from the dashboard or API
  block_duration: "1h"                # ban duration; h/m/s accepted
  max_404_attempts: 6                 # 404 probes tolerated per observation window; beyond it the score rises and blocking starts
  observation_period: "1m"            # length of the sliding observation window
  block_direct_ip: false              # leave false when rolling out; switch to true once no legitimate traffic is affected. Blocks requests reaching the gateway by raw IP with no Host
  forbidden_paths:
    - ".env"
    - ".php"
    - ".jsp"
    - ".asp"
    - ".aspx"
    - "/wp-admin"
    - "/wp-content"
    - "/phpmyadmin"

  global_rules:
    - name: "block_unsupported_ext"
      match:
        path_exact:
          - ".php"
          - ".php3"
          - ".php5"
          - ".php7"
          - ".phtml"
          - ".pht"
          - ".asp"
          - ".aspx"
          - ".ashx"
          - ".asmx"
          - ".jsp"
          - ".jspx"
          - ".cgi"
          - ".cfm"
      action: "deny"
      score: 30
      reason: "unsupported_ext_probe"

    - name: "secrets_and_vcs"
      match:
        path_exact:    ["/.git", "/.svn", "/.env", "/.htpasswd"]
        path_contains: ["/.git/", "/.env.", "/id_rsa", "/.ssh/", "/.aws/credentials", "/.docker/config.json"]
      action: "deny"
      score: 30
      reason: "secret_or_vcs_probe"

    - name: "admin_tool_probe"
      match:
        path_prefix:   ["/phpmyadmin", "/pma", "/adminer", "/manager/html", "/cgi-bin/"]
        path_contains: ["/vendor/phpunit/"]
      action: "deny"
      score: 30
      reason: "admin_tool_probe"

Leave block_direct_ip at false when first rolling this out, and turn it on once you have confirmed no legitimate traffic is affected; it immediately blocks requests that reach the gateway by raw IP with no Host header.

Field reference:

Field Type Description
enabled bool Enable scan protection. Can be toggled at runtime from the dashboard or API.
block_duration string How long a ban lasts, e.g. "1h" or "30m".
max_404_attempts int Maximum 404 probes tolerated within the observation window.
observation_period string Length of the sliding observation window.
forbidden_paths string[] Sensitive path prefixes and suffixes.
block_direct_ip bool Block requests that address the gateway by IP directly.
global_rules array Blocking rules pairing a match with an action. Supported actions: deny, tarpit, rate_limit, score, observe.

    state_file: data/connect-registry.json
    health:

      advertise_port: 443
      probe_path: /healthz        # Probed through the Connect reverse tunnel
      probe_interval: 5s
      probe_timeout: 2s
      ttl: 15s                    # Used only when service_registration is enabled
      fail_threshold: 2
      max_concurrent_probes: 32
      dns_registration:           # Publish passing domains to LiteDNS KV; default off
        enabled: false
        key_prefix: litedns/v1/records/
        record_ttl: 10
        kv_ttl: 15s
      service_registration:       # Register passing domains as LiteMesh services; default off
        enabled: false
    peers:
      private:

        max_registrations_per_minute: 30

  client:                         # Private node
    enabled: true
    name: private
    remote: https://connect.example.com/_litegate/connect/v1

    publish_streams: false

Cloud and Private normally use separate configurations and enable only their respective side. See docs/en/user/09-advanced/connect.md for the complete field reference, security boundaries, mTLS, multiple Cloud nodes, token rotation, and rollout procedure.

Health probing does not publish anything unless one of the two registration switches is enabled. dns_registration writes one expiring LiteDNS KV record per passing domain and Cloud node; service_registration is optional for applications that still use the LiteMesh service-discovery SDK. The switches are independent and both default to false.

Custom access log templates

log:
  format: json
  access_log:
    enabled: true
    stdout: true
    file_enabled: true
    file: ./logs/access.log
    template: '{client_ip} - [{timestamp}] "{method} {uri}" {status} {size_bytes} "{referer}" "{user_agent}" {cost_ms}'

template formats access log stdout and files. Leave it empty to preserve existing output. Application logs still use log.format; webhooks and dashboard data remain structured. Rotation, asynchronous output and level filtering still apply.

Fields: timestamp, client_ip, method, path, uri (including the query), host, status, size_bytes, cost_ms, upstream, route, site, trace_id, referer, user_agent. Timestamps use the existing structured log timestamp; costs are milliseconds with fractional precision. Empty Referer and User-Agent values become -. Missing values become -. Newlines, control characters, quotes and backslashes in field values are escaped to prevent forged log lines. Templates must be single-line; unknown or malformed placeholders fail configuration validation. This uses LiteGate {field} syntax rather than Nginx $variables.

Restart LiteGate after changing log.access_log.template. Only log.level is hot-reloadable among global log settings. MCP saves validate the configuration and request a reload, but a successful save does not mean startup-only settings are active. litegate -init includes an empty template and a custom template example in its generated configuration.

Upstream DNS resolvers

Changes to resolvers require a restart in Consul/LiteMesh config_watch mode. Filesystem reloads revalidate sites and reject removal of referenced resolvers. Stable ECH publication checks DNS every 30 minutes; failures retry every minute. To disable ECH, stop the instance, run litegate ech withdraw -config config.yaml to withdraw owned HTTPS records, then wait for caches to expire. Public-name certificate domains are derived at runtime without changing provider configuration.

resolvers:
  corp:
    servers: [192.168.1.53:53, 192.168.1.54:53]
    timeout: 2s

Proxy objects and named Services reference this configuration with resolver: corp. Servers must be literal IP:port addresses (bracket IPv6); the default per-server query timeout is 2 seconds. Truncated UDP replies retry over TCP. Failed queries try backup servers in the same DNS view; NXDOMAIN / NODATA do not. Explicit resolvers bypass system DNS, hosts and environment HTTP proxies. Unconfigured upstreams retain existing behavior. New connections re-query DNS; existing connections can be reused. See Upstream DNS.

Set site-level ech: ech.example.com or ech: ech.example.net to select the public name and its DNS provider; domains are derived automatically. Boolean true is accepted only with one group; false disables ECH. Groups independently manage keys, rotation, DNS publication and KV leases. Default prefixes are litegate/ech/<public_name>/. Root key_prefix is a parent directory; group-level key_prefix is an exact, unique prefix. Legacy single-group configs keep their original state path and litegate/ech/default/ prefix. Site selection reloads live; group configuration changes require restart.

Third-party ECH DNS providers implement plugin.HTTPSDNSProvider and register the https_records capability. LiteGate owns ECH keys, rotation, KV synchronization, leases and retries; plugins only publish/withdraw public HTTPS records. HTTPS-only providers need separate certificate coverage; their domain selectors are excluded from certificate DNS-01 routing at runtime.

SSH host certificates

Docker SSH also supports matching @cert-authority entries in known_hosts. Host certificates retain strict CA, principal and revocation verification; untrusted certificates never bypass pinned-key verification.
