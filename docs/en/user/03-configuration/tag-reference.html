LiteGate Service Tag Reference

Generated by internal/loader/tag_reference.go from the parser's property lists; it lists every tag the gateway accepts. See the Service Tag DSL guide for usage.

Two forms

Form Tags Use
Shortcut litegate.http.host/path/path_prefix/strip_path One route per service, no policy
Named resources litegate.entrypoints.*, litegate.http.routers.*, litegate.http.services.*, litegate.http.middlewares.*, litegate.http.serverstransports.* Several routes, middlewares, IDS, timeouts, retries

The two forms cannot be mixed. Property paths are lowercase; resource names use lowercase letters, digits, - and _. Unknown properties, invalid references and conflicts reject the whole instance (fail closed); diagnostics appear in the dashboard and MCP preview_service_tags.

Shortcut

Tag Value Meaning
litegate.http.host host list Unset: the catalog default_domain (<service>.<default_domain>)
litegate.http.path path Exact path; exclusive with path_prefix
litegate.http.path_prefix path Path prefix; / when neither is set. litegate.http.pathprefix is accepted too
litegate.http.strip_path bool Strip the matched path before forwarding

The shortcut compiles to an ordinary Router named main with the Router defaults: attached to web and websecure, targeting the registering service with the default policy. Use named resources for any policy.

Defaults

Omitted Effect
routers.<name>.entrypoints Attached to web and websecure
routers.<name>.service The only declared Service; the registering service with the default policy when none is declared; required when several are declared
Host condition Any Host on the entrypoints
Both Host and path condition (and no rule) Path prefix /<service> (- in the name becomes /), so services do not fight over the root
services.<name>.discovery.name The registering service

EntryPoint

Prefix litegate.entrypoints.<name>.

Property Value Meaning
address [ip]:port Creates a listener on an allowed port. TCP/UDP tags accept :port or 0.0.0.0:port and cannot claim an existing operator or static listener.
protocols http|tcp|udp Optional for HTTP; TCP/UDP require one explicit protocol matching the router.
tls.enabled bool TLS termination is supported on HTTP entrypoints; configure TCP passthrough on its Router.

TCP Router

Prefix litegate.tcp.routers.<name>.

Property Value Meaning
entrypoints list Explicit TCP entrypoints; TLS routes sharing a port merge before publication.
service name An explicitly declared local TCP Service of the registering workload.
match.sni list Exact or *.domain SNI for passthrough; exact then most specific wildcard; unmatched traffic is rejected.
tls.enabled bool TLS requires passthrough=true; tag-defined termination is unsupported.
tls.passthrough bool Forwards ClientHello and subsequent bytes unchanged; requires TLS and explicit SNI.

TCP Service

Prefix litegate.tcp.services.<name>.

Property Value Meaning
loadbalancer.server.port int TCP target port of the registering service; host mode requires its TCP published binding.

UDP Router

Prefix litegate.udp.routers.<name>.

Property Value Meaning
entrypoints list Explicit UDP entrypoints, one router per port; all TLS/SNI properties are rejected.
service name An explicitly declared local UDP Service of the registering workload.

UDP Service

Prefix litegate.udp.services.<name>.

Property Value Meaning
loadbalancer.server.port int UDP target port with UDP-specific published binding; endpoint changes or zero instances close old sessions.

HTTP Middleware

Written litegate.http.middlewares.<name>.<type>.<property>=<value>; the properties are the same as the config of that middleware type in site YAML and are validated by the middleware itself. Built-in types: api_key, basic_auth, chain, circuit_breaker, compress, cors, csrf, headers, ip_restriction, jwt_auth, limit_conn, mirror, ratelimit, redirect_regex, redirect_scheme, remote_auth, replace_path_regex, retry, rewrite, strip_prefix. A middleware has exactly one type. retry and circuit_breaker are deprecated (still working, with a load-time warning); use the Service's retry.attempts and circuitbreaker.* instead.

Route IP access control

The ip_restriction middleware accepts allow_ips and deny_ips as comma-separated IPv4, IPv6 or CIDR values. At least one is required; empty items and invalid addresses are rejected at load time. Deny takes precedence over allow. Reference it in a Router's middlewares to restrict that route while retaining global and site restrictions. It uses the ingress-resolved client IP; forwarding headers only affect IP resolution through trusted proxies.

litegate.http.routers.admin.match.path_prefix=/admin
litegate.http.routers.admin.middlewares=internal-only
litegate.http.middlewares.internal-only.ip_restriction.allow_ips=10.0.0.0/8,192.168.0.0/16,fd00::/8

Other tags

Tag Scope Meaning
litegate.swarm.lbswarm provider Swarm: true selects the Service VIP on an explicit non-ingress network; false keeps Task addresses. VIP rejects instance selectors, tag preferences and gray routing.
litegate.enable provider Docker/Swarm: explicitly opt the container in or out of discovery (true/false). Unset: any litegate.* label opts in.
litegate.docker.network provider Docker/Swarm: network whose address is used to reach the container.
litegate.docker.usehostport provider Docker: reach the container through its published host port (not supported on Swarm).
litegate.instance.labels.<key> instance Instance identity label, hard-matched by discovery.selector.match and IDS. A plain <key>=<value> metadata entry works too.
litegate.instance.meta.<key> instance Instance preference metadata, soft-matched by discovery.selector.meta with fallback.
litegate.instance.weight instance Load-balancing weight of this instance (positive integer).
litegate.instance.gray instance Marks this instance as a canary (gray) instance.
litegate.instance.version instance Instance version, exposed as the endpoint's version metadata.
litegate.instance.debugheaders instance Diagnostics: expose the selected upstream address and related debug headers on the response (true/false).
litegate[.<group>].tcp.port / udp.port stream Layer 4: the gateway listens on this port and forwards to the instance's registered port; the port must be in allowed_ports.
litegate[.<group>].tcp.tls.enabled / auto_cert / domains / cert_file / key_file / min_version stream TLS termination for the layer-4 TCP listener.

Instance tags (litegate.instance.*) may differ per instance; routing and resource tags must be identical on every instance of a service.

Removed

litegate.ingress.*, litegate.route.*, litegate.router.*, litegate.service.*, litegate.upstream.*, litegate.middleware.*, litegate.ids.*, litegate.site.*, litegate.entrypoint.*, litegate.io.*, litegate-http-* and any litegate.http.* key not listed above are removed. An instance carrying them is rejected as a whole.
