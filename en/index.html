Open source · MIT · single-binary gateway

One program for every way in to your services

LiteGate sits in front of your websites, APIs and private services. It accepts outside traffic, sets up HTTPS for you and forwards requests by rule. The job that used to take Nginx, Certbot, frp and a push service now takes one binary and a few lines of YAML.

Running in 5 minutes What can it do for me?
  • No external dependencies
  • Config changes without restarts
  • Linux / macOS / Windows
sites/app.yamla complete site
site: https://app.example.com  # auto certificate
/api: 127.0.0.1:8080            # API to the backend
spa: ./dist                     # the rest is the SPA
terminal
$ ./litegate
$ curl -I https://app.example.com/
HTTP/2 200

Built-in MCP · AI-native

Rather not write YAML? Tell an AI in one sentence

LiteGate ships an MCP server. Once Claude Code, Cursor or another AI assistant connects, it can read the existing configuration, generate a site, validate it, show the diff, save it and verify it with a real request. When something breaks, it can trace routes and read error logs.

  1. Connect your AI assistantRun one command locally, or turn on the token-protected SSE endpoint of a running gateway.
  2. Describe what you want"Send /api to 8080, serve ./dist for everything else, and enable HTTPS."
  3. Validated before it appliesThe AI validates and shows you the diff before saving and verifying. With release control on, changes land in a draft until you confirm.

A console, a status page and Grafana, one block of config each

The built-in console and status page need nothing else installed; their data comes from the traffic the gateway actually handles, with latency and errors for every site, route and backend instance at a glance. Already on Prometheus + Grafana? Import the official dashboard.

Why LiteGate

Simple things stay short, and complex ones need no new tool

One file to run

A single Go binary with no database or runtime dependencies. Download it, write one site file, start it.

Short configuration that keeps growing

Paths are keys, actions are values. Load balancing, CORS and rate limits go under the same route, and shorthand mixes freely with the full form.

Changes apply on save

Site files hot-reload when saved, with no process restart. Check before going live with litegate -t, just like nginx -t.

HTTPS ready by default

Write site: https://your-domain and certificates are issued and renewed automatically, over HTTP-01, TLS-ALPN-01 or DNS-01 for wildcards.

Visible and searchable

Built-in dashboard, access logs, Prometheus metrics and tracing. When a route does not match, ask the AI to simulate the request over MCP and show you why.

Extensible when you need it

litegate build --with compiles plugins into the binary: middleware, load balancers, DNS providers, service discovery and multi-tenant routing.

Architecture

One entrypoint between the Internet and all your services

On the left is HTTP, TCP and UDP traffic from the Internet; on the right are your backends: services discovered through tags, servers listed in site files, and private services connected through Connect reverse tunnels. Security, traffic control, certificates and observability all happen in the middle.

Quick start

Your first response in a minute

No config.yaml and no domain needed; try it on your own machine.

Install

Download a binary from Releases, or install with Go:

$ go install \
  github.com/jamesleeon/LiteGate/cmd/litegate@latest

Write a site

Create sites/hello.yaml in the working directory:

site: localhost
respond: "Hello, LiteGate!"

Start

From now on, changes in sites/ apply on save:

$ ./litegate
$ curl http://localhost/
Hello, LiteGate!
